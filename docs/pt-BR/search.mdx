Uma versão contém cerca de 187.000 módulos. A busca é como você sai de um palpite para
um caminho de arquivo.

## Buscar

```bash
cellar module search --name 'Passkey' --filter protocol
```

```
12 module(s) matched of 12 considered

WASmaxMdGetPasskeyRequestOptionsRPC   /Users/voce/.cellar/bundles/whatsapp-1044822804/modules/WASmaxMdGetPasskeyRequestOptionsRPC.js
WASmaxMdSetPasskeyPrologueRPC         /Users/voce/.cellar/bundles/whatsapp-1044822804/modules/WASmaxMdSetPasskeyPrologueRPC.js
…
```

Três coisas para casar, e elas se combinam:

| Flag | Casa contra |
| --- | --- |
| `--name` | O nome do módulo |
| `--source` | O código dentro do módulo |
| `--exports` | Os nomes que o módulo exporta |

```bash
cellar module search --name '^WAWeb' --source 'addonType' -C 2
cellar module search --exports 'sendStanza'
```

<Tip>
  Combinar `--name` com `--source` é muito mais rápido que só `--source`. O padrão de
  nome é aplicado no índice em memória, então só os arquivos que sobram são abertos.
  É a diferença entre ler quarenta arquivos e cento e oitenta mil.
</Tip>

### grep

O `cellar grep` é atalho para uma busca no código.

```bash
cellar grep 'disappearing_mode' --filter protocol -C 1
```


Como os módulos desempacotados são arquivos comuns, suas próprias ferramentas também
funcionam:

```bash
grep -rl 'disappearing_mode' ~/.cellar/bundles/whatsapp-1044822804/modules/
```

Flags úteis:

```bash
cellar module show WAWebSendMsgStanza --start 40 --lines 20   # um trecho
cellar module show WAWebSendMsgStanza --path-only              # só o caminho
```

## Lendo os resultados com cuidado

A busca informa `matched` (o total real) separado dos resultados devolvidos, e marca
`truncated: true` quando a lista foi cortada. Uma lista curta nunca é silenciosamente
uma lista completa. Módulos que não puderam ser lidos aparecem em `unreadable` em vez
de sumir.
